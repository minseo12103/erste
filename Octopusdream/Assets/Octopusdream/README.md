# Octopusdream — 숨바꼭질 프로토타입

Unity 6.3 URP로 만드는 Steam PC 팀 숨바꼭질 게임이다. 문어는 색칠과 주변색 복사로 숨고, 잠수부는 산소가 떨어지기 전에 작살로 문어를 찾는다. 현재 캐릭터는 교체 가능한 **구체 문어 / 원통 잠수부**다.

## Unity에서 바로 실행

1. `Assets/WOC/Scenes/WOC_Ct_Building_Park.unity`를 연다.
2. **Play**를 누른 뒤 Game 탭을 클릭한다.
3. 먼저 **혼자 연습**을 선택하면 Steam 접속 없이 조작과 라운드 흐름을 볼 수 있다.
4. 대기실에서 **연습 시작**을 누르면 문어로 시작한다. 잠수부로 연습하려면 중앙 작살 3.5m 안에서 `E`를 눌러 지원한 뒤 시작한다.

문어로 연습할 때 잠수부 봇은 시야를 회전하며 탐지하고, 작살은 발사하지 않는다. 문어 봇 두 마리도 함께 배치된다. 잠수부를 직접 선택하면 문어 봇을 대상으로 작살과 탐지를 확인할 수 있다.

현재 진입 씬은 **WOC_Ct_Building_Park**다. `Scenes/OctopusShapeLab.unity`는 초기 실험 기록으로 남아 있는 별도 씬이다.

## 조작

| 키 | 동작 |
|---|---|
| `WASD` | 이동 |
| `Space` / `Ctrl` | 상승 / 하강 |
| `F` | 문어 색칠 편집 시작 / 완료. 편집 중에는 제자리에 멈춘다. |
| 편집 중 좌클릭 드래그 | 문어 표면 색칠 |
| 편집 중 우클릭 드래그 | 문어 주위로 카메라 회전 |
| 편집 중 마우스 휠 | 브러시 크기 변경 |
| 편집창 `SOFTNESS` 슬라이더 | 외형의 부드러움 0~10 변경 |
| `V` | 바로 아래 표면의 텍스처 색과 재질 색을 읽어 문어 전체에 즉시 적용 |
| 대기실 중앙 작살 근처 `E` | 잠수부 지원 / 지원 취소 |
| 수색 중 문어 `E` | 충전된 먹물 사용 |
| 수색 중 잠수부 `E` | 적외선 탐지 |
| 잠수부 좌클릭 | 작살 발사 |
| `Esc` | 편집 종료 또는 마우스 해제 / 게임 조작 복귀 |
| `F1` | 도움말 표시 전환 |
| 포획 후 `Q` | 관전 대상 변경 |

문어는 3인칭, 잠수부는 1인칭이다. 편집창의 색상·채도 평면과 세로 밝기 막대로 색을 고르거나, RGB 값을 0~255로 직접 입력한다. 숫자 옆 `−`/`+`는 값을 1씩 바꾸며, 선택 색 미리보기로 확인할 수 있다. 숫자를 입력하는 동안 게임 단축키가 동작하지 않으며 Enter로 입력을 마친다. `V`나 전체 칠하기를 사용하면 기존 색칠을 덮어쓴다.

바닥에 가까이 내려오면 문어의 아랫부분이 표면에 붙는다. **SOFTNESS 5**는 둥근 몸체를 유지하면서 눌리고 가장자리가 처지며, **10**은 낮고 넓게 퍼져 단차를 따라 늘어진다. `Space`로 올라가 표면에서 떨어지면 공중 형태로 돌아간다. 이동용 충돌체는 안정적인 크기를 유지하고, 작살과 색칠은 변형된 문어 표면을 기준으로 판정한다.

## 라운드와 멀티플레이

- 기본값은 **숨기 30초 → 수색 180초**다. 잠수부는 숨기 시간 동안 장비 준비 화면에서 대기한다.
- 작살 한 번에 문어가 포획된다. 모두 잡히면 잠수부 팀이, 산소가 소진될 때 한 명이라도 살아 있으면 문어 팀이 승리한다.
- 방의 최대 인원은 호스트를 포함해 **20명**이다. 호스트가 술래 수와 시작 시점을 정한다.
- Steam 개발용 App ID는 **480**이다. Steam 방 만들기·검색·방 ID 참가·친구 초대 기능이 있다.
- 참가와 재참가는 대기실에서만 가능하다. 호스트가 나가면 방이 종료되며, 호스트 이전은 구현하지 않았다.

자세한 규칙은 [게임 기획](Docs/GameConcept.md), 두 PC 접속 방법과 확인 항목은 [멀티플레이 테스트 안내](Docs/MultiplayerTesting.md)를 참고한다.

## Windows 실행 파일

Unity 메뉴의 **Octopusdream → Build Windows Prototype**으로 개발 빌드를 만든다. 출력 위치는 `Builds/Windows/Octopusdream.exe`다. 다른 PC에 전달할 때는 `Octopusdream.exe`와 같은 폴더의 데이터·DLL·`steam_appid.txt`를 포함하여 **Windows 폴더 전체**를 복사한다.

## 확인한 결과

저장된 실행 보고서에서 다음을 확인했다. 2026-10-27에는 색상창과 접촉 변형을 갱신하고 아래 기능·접촉·LAN·화면 검사를 다시 실행했다.

- **Unity Play Mode:** 동작 검증 15개 통과, 런타임 오류 0개. 맵 충돌·스폰, 역할 배정, 숨기·수색 전환, 탐지·먹물·포획·승리, 색칠·SOFTNESS·주변색 복사를 포함한다. 근거: `Logs/Prototype/verification.json`.
- **Windows x64 개발 빌드:** 성공, 오류 0개·경고 0개. 근거: `Logs/Prototype/build.json`.
- **표면 접촉 검사:** 바닥의 0·5·10 형태, 계단 처짐과 관통 방지, 넓어진 면의 색칠과 빈 공간의 작살 판정, 공중 형태 복원 4개 검사 통과. 근거: `Logs/Prototype/surface-verification.json`. 5·10의 실제 비교 화면은 `Logs/Prototype/softness-5.png`, `softness-10.png`에 저장했다.
- **GPU 표면색 복사:** 읽기 불가능한 텍스처의 네 지점에서 UV 변환과 재질 색상을 적용한 결과가 읽기 가능한 기준값과 일치했다. 근거: `Logs/Prototype/graphics.json`.
- **실제 독립 실행 프로세스 2개의 LAN 연결:** 호스트·참가자 모두 통과. 같은 그림의 텍스처 해시, SOFTNESS 9, 순번을 붙인 이동 입력, 역할과 수색 단계 동기화를 확인했다. 근거: `Logs/Prototype/lan-host.json`, `Logs/Prototype/lan-client.json`.
- **표시된 Windows 창의 D3D12 화면:** 공원 맵, 색칠된 구체 문어, 한글 편집 UI가 정상적으로 보이고 조작 항목이 잘리지 않는 것을 캡처 이미지로 확인했다. 근거: `Logs/Prototype/preview-visible.png`, `Logs/Prototype/visual-visible.json`. 해당 실행 로그에 런타임 예외는 없었다.

실제 Steam 계정 두 개를 이용한 접속과 실제 20인 부하 테스트는 아직 확인하지 않았다. 현재 결과물은 기능을 확인하고 조정하기 위한 프로토타입이다.
